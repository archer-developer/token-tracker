# ADR-0001: Досрочное погашение и статус выплаты «отменено»

- **Статус:** принято
- **Дата:** 2026-11-11
- **Затрагивает:** `PaymentStatus`, `Instrument`, модалка «Погашено», календарь, перегенерация графика

## Контекст

Кнопка «Погашено» на экране инструмента переводила инструмент в статус `matured` и отмечала
**все** оставшиеся запланированные ненулевые выплаты (купоны и тело долга) как выплаченные —
каждую в её плановую дату, с записью в журнал денежных потоков.

Это верно только для погашения в срок. При досрочном погашении эмитент возвращает тело долга
раньше, а будущие купоны **не выплачиваются никогда**.

Реальный случай — HELIEUR28 (Hello каршеринг, Bynex), выпуск до 25.08.2028.
Выгрузка портала (`transactionHistory.xlsx`, 10.08–10.11.2026):

| Дата       | Операция                  | Сумма     |
| ---------- | ------------------------- | --------- |
| 06.11.2026 | Окупаемость инвестиций    | 9000 EUR  |
| 10.11.2026 | Получение дохода (за окт) | 70.32 EUR |

После 10.11.2026 по графику оставалось 22 купона на 1 504,76 EUR. Старое поведение записало бы их
в журнал как полученный доход, а тело долга — датой 25.08.2028, искажая XIRR, P&L, журнал и календарь.

## Решение

1. **Новый статус выплаты `cancelled`** (`PaymentStatus = 'scheduled' | 'paid' | 'missed' | 'cancelled'`).
   Отменённая выплата не наступит и не является просрочкой (в отличие от `missed`).
   Записи **не удаляются** из БД — информация сохраняется для истории/аналитики.
   Миграция схемы Dexie не нужна: индекс `status` хранит любые строковые значения.

2. **Модалка «Погашено»** получила:
   - поле **«Дата фактического погашения»** (по умолчанию — сегодня);
   - переключатель **«Отметить оставшиеся купоны как выплаченные»** (по умолчанию **выключен**).

3. **Логика** вынесена в `src/features/instruments/markMatured.ts` (`markInstrumentMatured`):
   - инструмент → `status: 'matured'`, новое поле `Instrument.redemptionDate` = фактическая дата;
   - запланированное погашение тела долга → `paid`, `paidAt` = фактическая дата, запись в журнал
     этой датой (а не плановой);
   - оставшиеся ненулевые купоны:
     - переключатель **выключен** → `cancelled`, без записей в журнал;
     - переключатель **включён** → прежнее поведение: `paid` в плановые даты + записи в журнал;
   - при выключенном переключателе нулевые купоны с датой **после** фактического погашения тоже
     становятся `cancelled` (чтобы не всплыть при «показывать нулевые выплаты»); нулевые периоды
     до погашения (например, до первой покупки) не трогаются;
   - уже выплаченные / пропущенные записи не изменяются;
   - всё выполняется в одной транзакции Dexie.

4. **Отображение:**
   - **Календарь** (`useCalendarPayments`) скрывает `cancelled`;
   - **Список выплат** инструмента показывает их во вкладке «История» с серым бейджем «Отменено»;
     у выплаченных записей с фактической датой вне планового окна показывается фактическая дата,
     история сортируется по фактической дате;
   - портфельные метрики, XIRR и график P&L учитывают только `scheduled`, поэтому `cancelled`
     исключаются автоматически.

5. **Перегенерация графика** (`regenerateSchedule`) сохраняет все записи, кроме `scheduled`
   (раньше — только `paid`/`missed`), иначе редактирование погашенного инструмента вернуло бы
   отменённые купоны в план.

## Рассмотренные альтернативы

- **Удалять будущие выплаты.** Просто, но теряется информация о недополученном доходе и её нельзя
  восстановить без перегенерации. Отклонено по требованию сохранять данные.
- **Отмечать как `missed`.** Семантически неверно: пропуск — это нарушение обязательств эмитента,
  а при досрочном погашении обязательства прекращены. Исказило бы статистику просрочек.
- **Автоматически выбирать режим по дате** (если фактическая дата < `endDate` → отмена). Неявно:
  пользователь может отмечать погашение в срок с опозданием. Явный переключатель понятнее.
- **Отменять купоны только после фактической даты погашения.** Отклонено: купон за последний
  период может прийти после возврата тела долга (HELIEUR28: тело 06.11, купон 10.11), а
  невыплаченные купоны до даты погашения пользователь отмечает вручную до нажатия «Погашено».

## Последствия

- `PaymentStatus` расширен — все `Record<PaymentStatus, …>` обязаны содержать `cancelled`
  (проверяется TypeScript).
- Отменённые выплаты попадают в бэкап как обычные записи; старые бэкапы импортируются без изменений.
- Переключатель по умолчанию выключен: при погашении **в срок** с оставшимися невыплаченными
  купонами пользователь должен включить его явно (либо отметить купоны вручную до погашения).
- Компоненты `Modal` и `Toggle` получили ARIA-роли (`dialog`, `switch`) — используются в e2e.

## Проверка

- Unit: `src/features/instruments/markMatured.test.ts` — оба режима, нулевые купоны,
  сохранение `cancelled` при перегенерации.
- E2E: `e2e/early-redemption.spec.ts` на реальных данных HELIEUR28 (`e2e/fixtures/helieur28.json` —
  инструмент, лоты, график и журнал из бэкапа от 2026-11-11): модалка, дата по умолчанию,
  переключатель, сверка выплат и журнала с выгрузкой портала, 22 отменённых купона на 1 504,76 EUR,
  скрытие из календаря.
- Ручная проверка на реальном бэкапе от 2026-11-11 (HELIEUR28, погашение 06.11.2026):
  тело 9000 EUR записано датой 06.11.2026, 22 купона (1 504,76 EUR) отменены, записи других
  инструментов не изменились; выплаты 10.08 / 10.09 / 10.10 / 10.11.2026 и погашение совпадают
  с выгрузкой портала.
